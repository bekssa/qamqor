# 🐘 Руководство для Backend Разработчика (Spring Boot)

Привет! Фронтенд проект `Qamqor` уже готов к интеграции с реальным бэкендом (API). Сейчас он использует моковые данные, которые подменяются на лету. Ниже описано всё, что нужно разработать на Spring Boot, чтобы они соединились.

## 📌 Архитектура и Переключение
На фронтенде предусмотрен удобный свитчер. Когда ваш API будет готов, достаточно будет изменить файл `.env` на фронтенде:
```env
VITE_API_MODE=real
VITE_API_BASE_URL=http://localhost:8080/api/v1  # Или адрес сервера
```
После этого фронтенд начнёт стучаться на ваш REST API. Ожидается, что ответы будут приходить в формате **application/json**.

---

## 🔗 Необходимые REST API эндпоинты

Фронтенд ожидает реализации следующих сущностей и маршрутов. Если какие-то методы будут отличаться (например, пути), мы сможем легко поправить это на фронтенде в классе `RealKamkorApi`.

### 1. Сервисные заявки (Service Requests)
Заявки на оказание помощи (например, покупка продуктов, сопровождение и т.д.)
* **`GET /api/v1/requests`**
  - **Описание**: Получить список всех заявок.
  - **Ответ**: Массив объектов ServiceRequest.
* **`GET /api/v1/requests/{id}`**
  - **Описание**: Получить заявку по ID.
* **`POST /api/v1/requests`**
  - **Описание**: Создать новую заявку. Тело: `{ title, description, authorId, category, location }`.
* **`PATCH /api/v1/requests/{id}/status`** (или PUT)
  - **Описание**: Изменить статус заявки (`open`, `in_progress`, `completed`, `cancelled`). Тело: `{ status }`.

### 2. Пользователи и Волонтёры (Users)
Пользователи системы делятся на роли (например, `volunteer`, `elderly`, `admin`).
* **`GET /api/v1/users?role=volunteer`** (или `/api/v1/volunteers`)
  - **Описание**: Получить список волонтёров.
* **`GET /api/v1/users/{id}`**
  - **Описание**: Извлечь профиль конкретного пользователя.

### 3. Отзывы (Reviews)
Рейтинговая система волонтёров или заказчиков.
* **`GET /api/v1/users/{userId}/reviews`**
  - **Описание**: Получить все отзывы, оставленные о пользователе (цели).
* **`POST /api/v1/reviews`**
  - **Описание**: Оставить новый отзыв. Тело: `{ authorId, targetId, rating, comment }`.

## 📦 Модели данных (DTO / Entities)
Ориентировочные интерфейсы для ответа API в JSON. Вы можете добавить поля (например `id` базы данных в виде UUID или Long).

**ServiceRequest**:
```json
{
  "id": "123",
  "title": "Помощь с покупкой продуктов",
  "description": "Нужно купить хлеб, молоко и кефир.",
  "authorId": "u3",
  "executorId": "u1", // опционально
  "status": "open", // open, in_progress, completed, cancelled
  "category": "Покупки",
  "location": "Алматы, Бостандыкский район",
  "createdAt": "2026-04-17T12:00:00Z"
}
```

**User**:
```json
{
  "id": "u1",
  "name": "Анна Иванова",
  "role": "volunteer", // volunteer, elderly, admin
  "phone": "+7 777 123 4567",
  "rating": 4.8 // опционально
}
```

**Review**:
```json
{
  "id": "rev1",
  "authorId": "u3",
  "targetId": "u1",
  "rating": 5,
  "comment": "Отличная помощь!",
  "createdAt": "2026-04-17T12:00:00Z"
}
```

## 🔒 Что ещё учесть (Технические моменты)
1. **CORS (Cross-Origin Resource Sharing)**: Ваш Spring Boot контроллер должен разрешать кросс-доменные запросы с фронтенда (обычно с `http://localhost:5173`), иначе браузер заблокирует запросы.
   * *Решение*: Аннотация `@CrossOrigin` над контроллерами или глобальный WebMvcConfigurer.
2. **Spring Security (Авторизация)**: У нас готов UI для Login и Password Recovery. Желательно, чтобы вы внедрили выдачу **JWT токенов** или `JSESSIONID` в ответах. В этом случае мы добавим на фронт перехватчик для отправки заголовка `Authorization: Bearer <token>`.
3. **Hibernate / Spring Data JPA**: Для создания таблиц в БД (PostgreSQL/MySQL) отлично лягут 3 основные сущности: `User`, `Request`, `Review` с их связями OneToMany/ManyToOne.
